# EYEPAINT — идеи и следующий горизонт

Живой бэклог после фаз **0–4** (см. `ROADMAP.md`).  
Формат каждой идеи: **что** → **зачем** → **как лучше** → **что даст**.

Скиллы: `eyepaint-app` (система), `eyepaint-features` (сейчас), `eyepaint-design` (UI).  
Правило: не спамить сущностями; новые вещи встраивать в **слои / инструменты / комнату**.  
Фаза 5 (тяжёлый AR/ML/аккаунты) — только spikes, пока ядро не стабильно.

**Статусы:** `idea` · `next` · `later` · `spike` · `done`

---

## Приоритетная лента (рекомендуемый порядок)

```text
A. Связь и камера с ПК
B. Guide-слой + фигуры + линейка
B0. Режим Свободный | AR (маркер → lock плоскости → plane-space жесты)
C. Сессия и позы сцены
D. UX-полировка Operate
E. Markerless / ML / teacher — later/spike
```

# A. Связь и камера

## A1. Reconnect комнаты · `next`

**Что.** Если WebRTC/MQTT отвалился — один CTA «Переподключить» с тем же кодом, без «создай комнату заново».

**Зачем.** Сейчас обрыв = потерянный поток сессии; художник не должен заново проходить QR-ритуал.

**Как.** Хранить host/join code (уже есть). На `error`/`idle` после `connected` — UI reconnect: повторный `joinRoom` / re-offer stream. Toast честный («связь пропала»). Не плодить новые коды без явного «Новый код».

**Даст.** Устойчивые сессии на слабом Wi‑Fi; меньше брошенных рисунков.

---

## A2. Экспозиция и фокус с ПК · `next`

**Что.** Слайдеры/тап-цель в панели «Телефон» (Рука), команды уже в data-channel (`exposure`, `focus`).

**Зачем.** Телефон на штативе далеко; крутить его нельзя.

**Как.** `MainPanel` tab Телефон → exposure ± и «тап-фокус» (координаты нормализованные → `roomCommands` → `cameraControls` на телефоне). Best-effort + disable если caps нет. Не дублировать весь CameraRoom UI на ПК.

**Даст.** ПК реально «мозг»; телефон остаётся сенсором.

---

## A3. Штатив-лок на телефоне · `next`

**Что.** Явный режим: огромная кнопка «Не трогать» / dim chrome / только статус эфира + wake lock.

**Зачем.** Случайные тапы сбивают кадр во время длинной сессии.

**Как.** Режим в `CameraRoom`: спрятать secondary controls, оставить exit/unlock. Связка с уже существующим штатив-UX и battery warn.

**Даст.** Спокойный эфир на 45–90 мин.

---

## A4. Честнее бейдж эфира · `later`

**Что.** Крупнее «камера → эфир · Мбит» на ПК; CTA «поставить 2K» если эфир << caps.

**Зачем.** Пользователь понимает, почему картинка мыльная.

**Как.** Усилить UI вокруг `videoQuality` stats; не обещать 4K.

**Даст.** Доверие и меньше «почему не 4K».

---

# B. Гиды как слои, фигуры, линейка

Это главный новый продуктовый блок. Модель: **не оверлей мимо слоёв и не слой на каждую линию**.

## B1. Тип слоя `guide` · `done` (MVP)

**Что.** Особый слой «Гид»: внутри — набор фигур; весь слой двигается теми же transform/проекцией/opacity/visible, что фото-слой.

**Статус.** В коде: `kind: 'guide'` + `shapes`, флаг `guideLayers`, пресеты пишут в слой, LayersPanel бейдж «Гид», проект/автосейв сериализует shapes. Один общий guide-слой (не спам).

---

## B2. Редактор фигур гида · `done` (MVP)

**Что.** В инструменте Гиды: пресеты **или** «Рисовать» — квадрат→прямоугольник, линия, овал; выбор фигуры → удалить / очистить.

**Статус.** Draw/select в Guides panel; жесты Руки двигают весь guide-слой. Ручки resize — позже.

---

## B3. Гид перспективы (1–2 точки) · `done` (пресет 1 точка)

**Что.** Пресет: горизонт + лучи в 1 точку схода.

**Статус.** Чип «Персп.» → shapes в guide-слое. Точки схода пока не drag-edit.

---

## B4. Линейка и калибровка «см» · `next` (после B1)

**Что.** Эталон: «этот отрезок = 20 см» → дальше измерения в см на плоскости листа. При отодвигании камеры масштаб меняется / устаревает честно.

**Зачем.** Пропорции «на глаз» слабо; нужна метрика относительно бумаги, не декоративная линейка.

**Как (честный псевдо-AR, не полный AR).**

1. **Калибровка:** фигура `ruler` / режим «Задать эталон» → две точки + ввод см (или пресет A4 21 см).
2. Хранить `pxPerCm` в системе координат **guide-слоя / плоскости листа** на момент калибровки.
3. Другие ruler-отрезки показывают см.
4. **Drift камеры:** при смене freeze/кадра/явном движении — бейдж «калибровка устарела → обновить»; не врать точность.
5. Ruler — тип shape внутри guide-слоя (не новый слой и не отдельная сущность вне слоёв).
6. Документировать ограничение: без маркера/гомографии это масштаб **в кадре**, стабильный пока камера на штативе.

**Даст.** «До точки ~20 см» при штативе; честный UX при движении камеры.

---

## B5. Режим «Свободный | AR» — lock плоскости по маркеру · `next` (MVP в коде)

**Что.** Два режима сверху по центру студии. AR один раз снимает плоскость с маркер-листа, сажает референс на неё, маркер убираешь — дальше работа на обычной бумаге, но жесты рефа в **координатах плоскости**. Камера дернулась → **Перекалибровать**.

**Имена табов (не «Просто»):**

| Tab | Смысл |
|-----|--------|
| **Свободный** | Как сейчас: pan/rotate/scale в экранных осях |
| **AR** | Калибровка маркером → жесты в plane-space |

Альтернативы, если «Свободный» не зайдёт: **Жесты** · **Экран**. Не использовать «Просто» / «Обычный» / «Без AR».

**Зачем.** Маркер не должен торчать в кадре всю сессию. Нужен разовый калибратор «как лежит бумага», после чего калька живёт на этой плоскости: «вверх» = вперёд по листу, проекция обновляется, не экранный translateY.

**Как — UX поток**

1. Tab **AR** → состояние `hunting`: «Ищи маркер…» / прогресс, пока детект не уверенный (порог + N стабильных кадров).
2. `locked`: референс (активный слой) выравнивается под pose/homography маркера.
3. UI: «Маркер можно убрать» + бейдж **Плоскость зафиксирована**.
4. Маркер в сторону → работа на чистом листе; plane остаётся в памяти сессии.
5. Жесты в AR после lock:
   - drag → движение **в плоскости** (u/v), не сырой screen XY;
   - «вверх» по экрану управления → вперёд по плоскости (меняется перспектива/`rotateX/Y` согласованно);
   - pinch/z → высота над плоскостью / scale в plane-space.
6. Кнопка **Перекалибровать** (всегда доступна в AR после первой удачной калибровки, и если трек/камера «поплыли»):
   - сброс lock → снова `hunting`;
   - не обязательно сбрасывать положение рефа в плоскости — опционально «сохранить offset» vs «сбросить на маркер»;
   - дефолт: переснять plane, **сохранить** относительный offset рефа в plane-space, если возможно.
7. Tab **Свободный** → классические жесты; plane lock можно помнить, но не применять (или спросить «выйти из плоскости?»).

**Как — техника (без аккаунтов)**

- Телефон: OpenCV.js / WASM Worker → ArUco (или 4 маркера на PDF-коврике) → pose + качество трека.
- Data-channel → ПК: matrix плоскости + `trackingQuality`.
- Studio хранит `PlaneLock { matrix, lockedAt, quality }`; transform слоя = plane ∘ localOffset.
- Флаг `arPlaneLock`. PDF/PNG маркера — `public/markers/` (`eyepaint-ar-marker-a4.png`, `eyepaint-ar-marker-card.png`, `marker.json`: DICT_4X4_50, center ID 0, corners 1–4). UI: «Скачать маркер». Перегенерация: `python3 scripts/generate-ar-marker.py`.

**Даст.** Ощущение настоящего AR под кальку: один раз поймал лист → рисуешь спокойно → перекалибровал, если штатив сдвинули.

---

## B6. AR без маркера (только лист) · `spike`

**Что.** Детект четырёхугольника бумаги + optical flow вместо ArUco.

**Зачем.** Без печати маркера.

**Как.** OpenCV quad + LK flow; или MindAR image track. Хрупко на бликах/руке. Не вместо B5 — усиление.

**Даст.** Удобство; стабильность ниже маркерного пути.

---

## B7. AR-стабилизация / метры через гомографию · `spike` / стык с B4

**Что.** После plane lock линейка (B4) берёт `pxPerCm` из известного размера маркера (мм на печати).

**Зачем.** «20 см» без ручного эталона, если маркер известного размера.

**Как.** Размер маркера в PDF фиксирован → scale из pose. Drift → Перекалибровать (B5).

**Даст.** Метрика и плоскость из одного ритуала.

---

# C. Сессия, позы, захват

## C1. Пауза таймера + мягкий конец · `next`

**Что.** Пауза сессии; звук/вибро/тост в конце без блокировки UI.

**Зачем.** Таймер есть, но рисование требует отойти/паузы.

**Как.** State `running|paused|ended` в session logic; CTA в tab Сессия.

**Даст.** Нормальный pomodoro без потери сессии.

---

## C2. Поза всей сцены · `next`

**Что.** Сохранять не только active layer, а снимок: все слои (включая guide) + ключевые настройки (opacity master?, colors per layer?).

**Зачем.** Сейчас поза «на один слой» слаба для multi-layer и гидов.

**Как.** `SavedScenePose` / расширить `SavedPose`; thumbnail композита; apply восстанавливает transforms по layer id/order. Импорт/экспорт JSON. Миграция со старых поз.

**Даст.** Быстрый возврат к сложной раскладке.

---

## C3. A/B камера ↔ референс · `next`

**Что.** Хоткей/жест: только камера / только реф / оба — без открытия панелей.

**Зачем.** Сверка рисунка с натурой одним тапом.

**Как.** Цикл master opacity или temp hide layers; hotkey в `hotkeys`. Не путать с Hide UI.

**Даст.** Скорость сверки в сессии.

---

## C4. ZIP галереи до/после · `later`

**Что.** Выгрузка всех снимков сессии пачкой.

**Зачем.** Скачивать по одному неудобно.

**Как.** Client-side zip (лёгкая либа) из `sessionGallery` dataURLs.

**Даст.** Архив прогресса за сессию.

---

## C5. Lineart / контур референса · `later` / лёгкий вариант `next`

**Что.** Опциональный edge-фильтр на фото-слой (не полный ML).

**Зачем.** Новичкам проще видеть силуэт.

**Как.** CSS/canvas Sobel-ish или готовый лёгкий filter; toggle на активном слое. Тяжёлый onnx — spike фазы 5.

**Даст.** Быстрая «обводка» без внешнего редактора.

---

# D. UX Operate

## D1. Пустые состояния панелей · `next`

**Что.** Цвета без палитры, позы пусто, слои без фото — одна фраза + один CTA.

**Зачем.** Пустота выглядит как баг.

**Как.** Единый паттерн empty в design skill; CTA «добавить фото» / «сохранить позу».

**Даст.** Понятный первый шаг в каждой панели.

---

## D2. Hide UI жёстче · `later`

**Что.** При скрытии chrome — только FAB/тонкий край; опционально жесты opacity без панелей.

**Зачем.** Сцена ещё важнее панелей на длинной сессии.

**Как.** Усилить существующий hide; не терять выход.

**Даст.** Максимум бумаги на экране.

---

## D3. Подписи рельсы · `later`

**Что.** Hover/long-press подпись инструмента (новички не помнят иконки).

**Зачем.** Онбординг не покрывает все tools.

**Как.** `HoverTooltip` / native title + mobile long-press toast. Не засорять rail постоянным текстом.

**Даст.** Discoverability без шума.

---

## D4. Контраст light-atmosphere · `later`

**Что.** Добить читаемость glass/chips/tips на светлой теме.

**Зачем.** Флаг lightTheme есть; на video всё ещё риск низкого контраста.

**Как.** Аудит токенов `--fg*` / `--panel-solid` в light; e2e/visual smoke.

**Даст.** Рабочий дневной режим у окна.

---

## D5. Онбординг «телефон подключён» · `later`

**Что.** Мини-тур после первого successful connect: двигай слой, opacity, hide UI.

**Зачем.** Welcome-тур не учит студию в эфире.

**Как.** Триггер на `roomStatus === connected'` один раз; ключ tour done.

**Даст.** Меньше «подключил и не понял что делать».

---

## D6. Единый destructive-угол · `next` (полировка)

**Что.** Везде один паттерн CornerAction/PanelFrame (сброс vs удалить).

**Зачем.** Уже чинили sticky; нужна дисциплина во всех панелях.

**Как.** Следовать `eyepaint-design` § CornerAction; аудит Settings/Colors/Poses/Project.

**Даст.** Предсказуемый chrome, меньше багов скролла.

---

# E. Обучение и «вау» (осторожно)

## E1. Уроки 2.0 — чеклист в сессии · `later`

**Что.** Не только старт пресета, а шаги: «включи гид → opacity 40% → …».

**Зачем.** Карточки Welcome заканчиваются на входе в Studio.

**Как.** JSON шагов урока + тонкий checklist overlay; без тяжёлого LMS.

**Даст.** Обучение внутри практики.

---

## E2. Teacher → student · `spike`

**Что.** Роль учителя транслирует transform/guide ученику по data-channel.

**Зачем.** Разбор работ / урок на двоих.

**Как.** ROADMAP фаза 5; отдельная роль, синхрон состояния. Высокая сложность.

**Даст.** Парное обучение; не начинать до стабильного P2P reconnect.

---

## E3. ML-контур / аккаунты / мультикомнаты · `spike` / вне скоупа

См. ROADMAP фаза 5 и «вне скоупа». Не смешивать с B/C/D без отдельного решения.

# Как брать в работу

1. Открыть `eyepaint-app` + этот файл + `eyepaint-design`.  
2. Выбрать идею со статусом `next` из ленты A→B→C.  
3. Для B1/B2/B4 — сначала модель данных и антиспам слоёв, потом UI.  
4. Зафлагать эксперимент.  
5. E2E на священные пути (join, слои, hide UI).  
6. После мержа: обновить статус здесь и skills, если поведение продукта изменилось.
