# EYEPAINT — продуктовый roadmap

Живой план доработок. Цель продукта: **рисовать с референса через «кальку»** — телефон как камера над листом, ПК как студия управления.

Стек сейчас: Vite + React + TS, GitHub Pages, WebRTC (Trystero MQTT), Tailwind v4.

---

## Принципы

1. **Сцена важнее панелей** — UI не должен перекрывать бумагу/камеру без нужды.
2. **Телефон = сенсор, ПК = мозг** — на телефоне минимум действий, на ПК — точная настройка.
3. **Честный эфир** — всегда видно «с камеры» vs «в эфир», без ложных 4K.
4. **Малыми релизами** — каждая фаза сама по себе полезна после мержа.
5. **Без тяжёлого бэкенда** — пока всё peer-to-peer + localStorage; облако только если без него никак.

## Фаза 1 — Связь и камера (максимальный эффект)

Топ из обсуждения: QR, фокус/экспозиция, заморозка, статус эфира.

### 1.1 QR вместо ручного кода
- ПК: QR с URL `…/Eyepaint/?join=CODE` или payload `eyepaint://join/CODE`
- Телефон: камера/файл QR **или** deep-link из адресной строки
- Фолбэк: текущий ввод кода остаётся
- Либа: лёгкий QR encode (без тяжёлых зависимостей по возможности)

### 1.2 Тап-фокус и экспозиция (телефон)
- Тап по превью → `track.applyConstraints` / `ImageCapture` / advanced constraints где доступно
- Показать маркер фокуса на 0.6s
- Слайдер компенсации экспозиции (−2…+2), если браузер даёт

### 1.3 Заморозка кадра
- Кнопка на телефоне и команда с ПК
- Вместо live track — последний video frame через canvas `captureStream` **или** `ImageCapture.grabFrame` + статичный bitmap в стриме
- Индикатор «❄ Заморожено» на обоих концах

### 1.4 Штатив-режим телефона
- Крупный статус, огромная «Подключиться / Отключиться»
- Свернуть инструкцию в «Как это работает?»
- Wake Lock + предупреждение батареи &lt; 15%

### 1.5 Честный статус качества (усиление)
- Бейдж на ПК: `эфир 1080×1920 · ~X Мбит`
- Если эфир << потолок — CTA «поставить 2K»

**Готово когда:** с ПК можно создать комнату → телефон входит по QR → тап фокусирует → заморозка работает → батарея предупреждает.

## Фаза 2 — Студия рисования (ПК)

### 2.1 Режим «калька»
- CSS/canvas фильтр на слое камеры: контраст + лёгкое осветление середины
- Слайдер силы 0–100%
- Не трогает референс

### 2.2 Лупа
- Hold хоткей (например `Alt` / назначаемый) + область под курсором
- Масштаб 1.5× / 2× / 3×
- Не двигает transform референса

### 2.3 Гиды пропорций
- Пресеты: лицо (оси), фигура (рост), перспектива (1–2 точки), сетка 3×3
- Отдельная прозрачность гида
- Вкл/выкл, не в позах по умолчанию (опционально сохранять)

### 2.4 Слои референса
- До 2–3 изображений: основной + вспомогательный
- У каждого opacity / visible / order
- «Камера/Галерея» добавляет во вспомогательный, если основной занят

### 2.5 Позы 2.0
- Thumbnail превью (canvas snapshot позы)
- Экспорт/импорт JSON пресета
- Опционально: включить opacity + color selection в позу

**Готово когда:** художник может включить кальку + лупу + гид лица и сохранить позу с превью.

## Фаза 3 — Цвета 2.0

Уже есть: точность, допуск, пипетка, все/инверт.

### 3.1 Кисть-маска зоны
- Рисование маски на референсе (оставить / убрать)
- Комбинируется с выбранными цветами (AND/OR)

### 3.2 Пресеты палитр
- Кожа / небо / тени / монохром — стартовые наборы или быстрые фильтры hue-range

### 3.3 Покрытие кадра
- «Выбор покрывает ~N% пикселей» — сразу видно, что допуск широкий

### 3.4 Сохранённые пользовательские палитры
- localStorage список избранных hex-наборов

**Готово когда:** можно вырезать кистью зону лица и видеть % покрытия.

## Фаза 4 — Сессия, обучение, полировка UX

### 4.1 Онбординг 3 шага
- Первый запуск: ПК код → телефон → прозрачность
- Скип + «не показывать снова»

### 4.2 Таймер сессии
- 25 / 45 / 90 мин, мягкий тост, пауза
- Не блокирует UI

### 4.3 До / после
- Авто-композит в старте сессии (опционально) + ручной «снимок прогресса»
- Галерея сессии в localStorage / скачивание ZIP по одному

### 4.4 Уроки-карточки
- Статичные пресеты в `public/lessons/*` + JSON (имя, референс, стартовая поза, гид)
- Welcome: «Урок: портрет 3/4»

### 4.5 Тема кальки
- Светлая / тёмная атмосфера UI под комнатный свет (не ломая бренд)

### 4.6 PWA
- `manifest.webmanifest`, иконки, `display: standalone`
- Install prompt на Welcome (телефон)

**Готово когда:** новый пользователь проходит онбординг, ставит PWA, проходит урок с таймером и сохраняет до/после.

## Фаза 5 — «Вау» (сложное, отдельно оценивать)

Каждый пункт — отдельное исследование / spike перед полной реализацией.

| Идея | Сложность | Риск | Подход |
|------|-----------|------|--------|
| AR-выравнивание листа | Очень высокая | Нестабильно в браузере | Spike на WebXR / OpenCV.wasm / детект четырёхугольника |
| ML-контур референса | Высокая | Размер бандла, качество | onnxruntime-web, модель edge detect / lineart; опциональная загрузка |
| Учитель → ученик | Высокая | Синхрон состояния | Отдельная роль `teacher`, трансляция transform по data-channel |
| Мультикомнаты / аккаунты | Высокая | Нужен бэкенд | Отложить, пока P2P хватает |

**Правило:** в фазу 5 не входим, пока 1–4 не стабильны на S25+ и десктопе Chrome/Safari.

## Критерии качества на каждый PR

- [ ] `npm run build` + `npm run lint`
- [ ] Не ломает существующий join по коду
- [ ] На телефоне не появляется «вторая студия» — только камера/стрим
- [ ] На ПК сцена остаётся full-bleed (один док)
- [ ] Есть способ выключить новую фичу (флаг или явный toggle)
- [ ] Коммит: `feat|fix|refactor: … — компоненты`

---

## Метрики «стало лучше» (качественные)

- Время от открытия сайта до первого полезного стрима &lt; 60 с (QR + онбординг)
- Пользователь понимает, почему 4K «не летает» (бейдж эфира)
- За сессию рисования UI прячется в 1 тап и возвращается в 1 тап
- Поза восстанавливается с узнаваемой картинкой, не только цифрами

## Вне скоупа (пока сознательно нет)

- Замена MQTT-сигналки, пока она стабильна
- Полный редактор изображений
